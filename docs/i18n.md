# Turkish and English interface

The default language is Turkish. `LocaleProvider` receives the `kie-locale`
cookie from the root layout, so server HTML and hydration use the same locale.
The header's language button updates React context immediately without a page
reload or router refresh. The preference cookie lasts one year. The account
settings selector uses the same context. Theme preference remains independent.

`src/lib/i18n/en.json` maps Turkish source messages to English. Both languages
are available locally; switching languages never calls a translation service.
Routes, identifiers, stored enums, currencies and user-entered values stay stable.
This is interface localization; route URLs and SEO metadata retain their current
structure. User listings and conversations are not machine-translated.

## Adding interface text

Use the localized React elements in either server or client components:

```tsx
import * as I18n from '@/components/i18n/Localized';

<I18n.button aria-label="Kaydet">Kaydet</I18n.button>
<I18n.input placeholder="İlan başlığı" name="title" />
<I18n.p><I18n.Raw>{listing.description}</I18n.Raw></I18n.p>
<I18n.Formatted kind="formatPrice" args={[listing.price, listing.currency]} />
```

Add the corresponding English entry to the catalog. Elements translate their
direct text/fragment children and `title`, `aria-label`, `placeholder`, and `alt`.
They leave handlers, refs, form values and element children intact. Wrap arbitrary
user content in `I18n.Raw`, or use `translate="no"` on a localized leaf element.
An option without an explicit value retains its Turkish source label as its
submitted value. Prefer explicit values for new options.

For strings used outside JSX (for example suggested chat replies), client
components can use `const { locale, t } = useLocale()`. Use `I18n.Text` for rich
inline text without an extra DOM element. For sentences whose word order changes,
prefer a complete message to multiple translated fragments.

Templates use numbered placeholders, e.g. `Fotoğraf {0} / {1}`. The translator
matches a complete source message and preserves inserted user content. Unknown
messages remain unchanged. `I18n.Formatted` handles numbers, dates, money and
relative time with the selected locale; it never converts currency amounts.

## Verification

- `npm test`: catalog coverage, translation templates, SSR, user-content handling,
  form-value preservation and the existing project tests.
- `npm run lint` and `npm run typecheck`.
- With the local server running, `npm run test:i18n`: guest-page navigation,
  instant switching, preserved input values, theme independence, preference
  persistence, and responsive checks from 320px to 1440px. It does not submit forms
  or sign in. Screenshots are written to the ignored `responsive-shots/` folder.
- `npm run build`: production compilation of all routes.
